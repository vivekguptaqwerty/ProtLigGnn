# Graph Preprocessing Pipeline Analysis

This document details the complete step-by-step pipeline that transforms raw protein-ligand structural files into PyTorch Geometric graph representations for model training.

---

## 1. Complete Preprocessing Pipeline Flow

```text
Raw Structural Files (PDB & SDF)
     │
     ├─► Ligand SDF Parsing (RDKit) ──► 3D Conformer Coordinates & Atoms
     │                                        │
     │                                        ▼
     │                                  Feature Engineering & Covalent Bonds
     │                                        │
     │                                        ▼
     │                                  Ligand PyG Graph (Data)
     │                                        │
     │                                        ▼
     └─► Protein PDB Parsing (BioPython)      │
               │                              │
               ▼                              │
         Filter Residues within 6Å of Ligand ◄┘ (Using Ligand Coordinates)
               │
               ▼
         Feature Engineering & Distance-based Connectivity (<= 8Å)
               │
               ▼
         Protein Pocket PyG Graph (Data)
               │
               ▼
    PDBbindPairDataset Object (List of 4-tuples: ligand_graph, protein_graph, affinity, pdb_id)
               │
               ▼
   PyTorch Geometric DataLoader ──► CPU-to-GPU Transfer ──► Model Forward Pass
```

---

## 2. Preprocessing Pipeline Stages

### Stage 1: Raw Files Input
The raw dataset consists of protein-ligand complexes organized in directories:
- **Protein Structure:** `[pdb_id]_protein.pdb`
- **Ligand Structure:** `[pdb_id]_ligand.sdf`
- **Affinity Label:** Retrieved from PDBbind index files (`INDEX_general_PL.2020R1.lst`).

### Stage 2: Ligand SDF Parsing
The ligand molecule is parsed from SDF format using RDKit:
- Functions: `load_ligand_molecule(ligand_path)` uses `Chem.SDMolSupplier` or `Chem.MolFromMol2File`.
- Validation: Verifies that the molecule is readable and contains a valid 3D conformer with atom coordinates.

### Stage 3: Ligand PyG Graph Construction
The parsed ligand molecule is converted into a PyTorch Geometric `Data` object:
- **Node Features (`x`):** 9-dimensional vector representing atomic properties (atomic number, hybridization, implicit valence, degree, formal charge, ring membership, aromaticity).
- **Edge Index (`edge_index`):** 2D long tensor generated from covalent bonds, represented symmetrically (bidirectional).
- **Positions (`pos`):** 3D coordinates of each atom.

### Stage 4: Protein PDB Parsing
The protein PDB file is parsed using the BioPython `PDBParser` class:
- Reads structure, models, chains, and residues.
- Ignores non-amino acid residues (HETATMs).

### Stage 5: Pocket Residue Extraction
To focus GNN computation on binding pocket chemistry:
- Computes distances between all non-hydrogen atoms of standard residues and all ligand atoms.
- **Criteria:** A residue is included in the pocket if any of its atoms are within **6.0Å** of any ligand atom.

### Stage 6: Protein Pocket Graph Construction
Selected pocket residues are represented as a PyTorch Geometric `Data` object:
- **Nodes:** Represented at the residue level (either alpha carbon `CA` coordinate or center of mass).
- **Node Features (`x`):** 30-dimensional vector representing residue traits (one-hot amino acid code, mass, aromatic, polar, hydrophobic, basic, acidic, glycine/proline indicators).
- **Edge Index (`edge_index`):** Generated by connecting residues within **8.0Å** of each other.
- **Positions (`pos`):** 3D coordinates of each residue center.

### Stage 7: Dataset Object Instantiation
The `PDBbindPairDataset` class holds a list of processed tuples:
- Each sample is a tuple: `(ligand_graph, protein_graph, affinity_label, pdb_id)`.
- Features, labels, and graphs are pre-computed and held in system memory.

### Stage 8: Training & Batching
During training, the custom DataLoader batches these tuples:
- Graphs are collated into `Batch` objects (merging block-diagonal adjacency matrices).
- Batches are copied from CPU RAM to GPU VRAM before the forward pass.
