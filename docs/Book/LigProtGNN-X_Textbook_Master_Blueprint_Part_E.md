# LigProtGNN-X Textbook Master Blueprint (BGS v1.0)

# Part E — Figures, Tables, Algorithms & Visual Communication Specification

> **Objective:** Define a unified visual language for the LigProtGNN-X textbook so that every figure, table, algorithm, workflow, and illustration follows consistent publication-quality standards.

---

# 1. Purpose

Visual elements are not decorative. They are instructional components that reinforce scientific understanding, mathematical intuition, and engineering implementation.

Every visual artifact shall contribute meaningful educational value.

---

# 2. Visual Design Philosophy

Each figure should answer at least one of the following:

- What does this concept look like?
- How does the workflow progress?
- How do components interact?
- Why is the proposed approach better?
- How is LigProtGNN-X implemented?

Prefer explanatory diagrams over artistic illustrations.

---

# 3. Figure Categories

The textbook should include, where appropriate:

- Conceptual diagrams
- Biological illustrations
- Molecular interaction diagrams
- Protein structure schematics
- Data pipeline diagrams
- Training and inference workflows
- Repository architecture maps
- Software component diagrams
- Graph neural network message passing
- Transformer attention flows
- Embedding space visualizations
- Calibration plots
- Reliability diagrams
- Explainability heatmaps
- Ablation result summaries
- Timeline diagrams
- Phase evolution diagrams

---

# 4. Figure Standards

Every figure shall contain:

- Figure number
- Descriptive title
- Caption
- Educational purpose
- Reference in surrounding text
- Source (repository, experiment, or conceptual)
- Related chapter(s)

Figures must be vector-friendly wherever possible.

---

# 5. Diagram Specification

Every diagram should define:

- Nodes
- Edges
- Labels
- Legend
- Layout
- Direction of information flow
- Key annotations

The specification should be detailed enough for independent recreation.

---

# 6. Table Standards

Every table shall include:

- Table number
- Title
- Caption (where appropriate)
- Units
- Source
- Discussion in text

Recommended table types:

- Dataset summaries
- Model comparisons
- Hyperparameters
- Experimental metrics
- Phase evolution
- Component mapping
- Biological terminology
- Mathematical notation
- Advantages vs. limitations

---

# 7. Algorithm Standards

Each algorithm should contain:

- Algorithm number
- Objective
- Inputs
- Outputs
- Preconditions
- Pseudocode
- Complexity analysis
- Engineering notes
- Repository mapping
- Related equations

Maintain a consistent pseudocode style throughout the book.

---

# 8. Color and Typography Guidelines

Visuals should prioritize readability.

- Use consistent fonts.
- Maintain accessible contrast.
- Avoid unnecessary decorative effects.
- Use color only to emphasize meaning.
- Ensure grayscale readability for printed versions.

---

# 9. Cross-Referencing

Every figure, table, and algorithm must be referenced within the chapter text.

Avoid orphaned visuals.

Maintain:

- Figure index
- Table index
- Algorithm index

---

# 10. Asset Library

Maintain a reusable asset library containing:

- Source diagrams
- Editable vector graphics
- Experimental plots
- Architecture figures
- Icons
- Workflow diagrams

Each asset should include version information and provenance.

---

# 11. Repository Integration

Where applicable, visuals should be generated from or linked to repository artifacts, experiments, or evaluation outputs.

Clearly distinguish between:

- Conceptual figures
- Repository-derived figures
- Experimental figures
- External reference figures

---

# 12. Quality Checklist

Before accepting any visual artifact verify:

- Caption is complete.
- Numbering is correct.
- Cross-reference exists.
- Educational purpose is clear.
- Labels are readable.
- Visual matches repository implementation where applicable.
- Asset is stored in the central asset library.

---

# End of Part E
